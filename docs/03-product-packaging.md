# 「流觞」产品包装与路演叙事

## 1. 产品名与标语

产品名：流觞

主标语：

> 有人在上游留下了一句话。

备选标语：

- 刷到这里时，有句话正好漂来。
- 让过去某个陌生人的一句话，抵达此刻的你。
- 不是推荐给你的人，是漂到你面前的一句话。
- 刷视频时，接住一句来自上游的回响。

一句话介绍：

> 「流觞」是一个 AI 短视频卡片体验。当用户在某类内容上停留时，AI 会把视频内容、用户此刻的停留状态和陌生人过去留下的回响句匹配起来，生成一张自然浮现的流觞卡。

## 2. 产品关键词

- 停留
- 回响
- 上游
- 后来者
- 旧事
- 收下
- 留一句
- 封存

## 3. 命名体系

| 功能 | 推荐命名 | 说明 |
| --- | --- | --- |
| AI 生成/匹配出的卡片 | 流觞卡 | 核心体验 |
| 陌生人留下的一句话 | 回响 | 比评论更轻，也更有时间感 |
| 用户收藏一句话 | 收下 | 比收藏更有人情味 |
| 用户投稿一句话 | 留一句 | 行动成本低 |
| 回响的来源 | 上游 | 对应曲水流觞的意象 |
| 看到这句话的人 | 后来者 | 对应“后之览者” |
| 同一主题下的用户 | 同席者 | 可替代“好友/群聊” |
| 主题结束后的沉淀页 | 封存 | 对应年度记忆与档案 |

## 4. 视觉方向

整体气质：短视频界面的即时感 + 纸笺/水流的克制诗意。

建议风格：

- 背景是沉浸式竖屏视频，不做传统首页。
- 流觞卡采用半透明纸笺感，不要做厚重弹窗。
- 动画像“漂来”，不是“弹出”。
- 颜色控制在深色视频背景、米白卡片、青绿色水痕、少量暖金强调之间。
- 字体要清晰，回响句是视觉中心。
- 调试模式可以用细线和标签展示 AI 判断过程，但正式体验不要技术感太重。

卡片文案层级：

```text
上游来信
你在这条河边停了一会儿。

“我也是很久以后才发现，所谓回家，不一定是回到一个地方。”

来自 127 天前的一次停留

[收下] [留一句] [继续刷]
```

## 5. 路演开场

30 秒版本：

```text
我们做的是「流觞」。

短视频里有很多时刻，用户并不是因为功能停下来，而是因为某个画面、某句话，让他突然想起以前的事。

「流觞」想接住这个瞬间。当用户在某类内容上停留时，AI 会识别视频的情绪和主题，再从过去陌生人留下的回响中，匹配一句最适合此刻的话，变成一张自然浮现的卡片。

它不是评论区，也不是社交群。它更像一只从上游漂来的杯盏：有人曾经留下了一句话，而你刚好刷到了。
```

90 秒版本：

```text
赛题叫“刷到懂你的瞬间”。我们理解的“懂你”，不是 AI 直接说“我懂你”，那很容易冒犯，也很容易变成煽情文案。

真正让人停下来的，常常是刷到某个视频时，突然想起以前的事。

所以我们做了「流觞」：一个出现在短视频信息流里的 AI 卡片体验。

用户刷视频时，系统会观察停留、重复观看、点赞、评论展开等行为。AI 会结合视频内容，判断用户是否进入了某个瞬间，例如归乡、久别、疲惫、旧友、错过。

当这个瞬间足够清晰时，一张流觞卡会自然浮现。卡片上不是 AI 生成的大段文字，而是一句过去某个陌生人留下的话。

用户可以收下，也可以留一句给后来者。于是一次短暂的停留，就变成了跨越时间的对上。
```

## 6. Demo 叙事

### 第一幕：正常刷视频

画面：用户进入一个 Web 版短视频流。

讲法：

> 一开始它和普通短视频流一样，用户可以直接刷走。我们不希望 AI 一上来就打断用户。

### 第二幕：用户开始停留

画面：连续刷到奥德赛、归乡、城市夜路等内容，用户停留时间变长。

讲法：

> 当用户连续停留在相近主题上，系统会认为这里可能出现了一个“懂你的瞬间”。

### 第三幕：流觞卡出现

画面：卡片从视频下方浮现。

讲法：

> 这时 AI 不直接评价用户，而是把过去某个陌生人的一句话漂过来。

卡片展示：

```text
有人在上游留下了一句话

“我也是很久以后才发现，所谓回家，不一定是回到一个地方。”

来自 127 天前的一次停留
```

### 第四幕：用户留一句

画面：用户输入一句话。

讲法：

> 用户也可以只留一句很短的话。它会经过 AI 审核和标签化，在未来漂到另一个相似的时刻。

### 第五幕：上游封存

画面：打开上游页，看到同一主题的回响和封存短序。

讲法：

> 当一轮流觞积累到一定数量，它会被封存成一个主题档案。这里才是“后之览者，亦将有感于斯文”。

## 7. 评委可能追问与回答

### 这和评论区有什么区别？

评论区是围绕视频展开的即时讨论，流觞是围绕用户此刻停留状态进行的跨时间匹配。

评论区问的是“大家怎么看这个视频”，流觞问的是“此刻哪一句过去的话会和你对上”。

### AI 在哪里？

AI 不只是生成文字。它参与三件事：

- 理解视频内容和情绪标签。
- 判断用户是否进入适合出卡的瞬间。
- 在回响库中匹配最合适的一句话，并生成克制的卡片表达。

### 为什么不直接让 AI 生成一句话？

因为赛题强调“刷到懂你的瞬间”。陌生人过去留下的一句话，比 AI 现编的话更有真实感和时间感。AI 的价值在于匹配，不是抢走人的表达。

### 为什么不做群聊？

群聊太重，会引入社交关系、审核、隐私和反骚扰问题，也会稀释卡片体验。第一版用“同席者”和“留一句”保留人的存在，但不展开成完整社交平台。

### 如何控制成本？

第一版可以使用预设视频标签和回响库，只在关键节点调用 AI。大量卡片可以复用同一主题下的回响，不需要每次实时生成。

### 如何避免冒犯用户？

产品不直接说“你很孤独”或“我懂你”。它只说：

> 你在这条河边停了一会儿。

然后给出一句来自上游的话。用户可以收下，也可以继续刷走。

## 8. 第一版展示重点

必须让评委看到：

- 卡片是自然出现在信息流里的。
- 用户为什么会停下来。
- AI 如何把视频、停留行为和陌生人回响连接起来。
- 用户留下的一句话如何成为下一次流觞。

不要把重点放在：

- 好友列表有多完整。
- 群聊功能有多复杂。
- 年度报告有多少图表。
- 后台管理有多少字段。

这些可以有，但不能抢走“那一张卡”。

## 9. 推荐首页第一屏

第一屏不要做营销 Landing Page，直接进入产品体验。

布局建议：

- 中央：竖屏视频
- 右侧：点赞、评论、收下、分享
- 左侧或顶部：推荐 / 关注 / 流觞
- 底部：视频标题和作者
- 右上角：同席者小入口，不展开成聊天
- 调试开关：演示时打开，展示 AI 标签和触发进度

当卡片出现时，屏幕其余元素降低存在感，让回响句成为视觉中心。

## 10. 最小可开发版本

前端：

- 视频流页面
- 流觞卡组件
- 留一句弹层
- 上游封存页
- 我的收下页面
- 演示调试面板

后端：

- 视频列表 API
- 观看事件 API
- 触发判断 API
- 回响匹配 API
- 留一句 API
- 封存页 API

数据：

- 8-12 个预设视频
- 30 条预设回响
- 5 个主题：归乡、旧友、疲惫、成长、城市
- 1 个演示用户
- 1 个“后来者”演示用户

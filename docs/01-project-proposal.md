# 「流觞」项目方案

## 1. 项目定位

赛道：赛道一，AI 体验：刷到懂你的瞬间

项目名：流觞

一句话：

> 刷视频时，AI 把你此刻的情绪，和某个陌生人过去留下的一句话，对上了。

核心体验不是“功能多”，而是“停下来”。用户在短视频信息流中连续停留于某类内容时，系统不弹出工具面板，而是自然浮现一张「流觞卡」：它像从上游漂来的杯盏，带着过去某个人留给后来者的一句话。

## 2. 情感命题

“刷到懂你”不是 AI 对用户说“我知道你是谁”，那会冒犯、油腻、甚至让人警惕。

更克制的表达是：

> 有人，在某个和你一样的夜晚，刷到这里，写下了一句话。你现在刷到了它。

用户停下来的原因不是信息量，而是被某种过去的经验、情绪、记忆轻轻碰到。这个产品要捕捉的不是“我喜欢什么”，而是“我此刻为什么会被这个视频绊住一下”。

## 3. 核心机制

流觞由四个动作组成：

1. 看见：用户刷视频，系统记录停留、重复观看、点赞、评论展开等行为。
2. 判断：AI 结合视频内容和用户行为，判断用户是否进入一个可命名的瞬间，例如“归乡”“久别”“疲惫的理想主义”“突然想起以前”。
3. 对上：AI 从回响库中匹配一句陌生人过去留下的话。
4. 传下去：用户可以收下这句话，也可以留下一句给后来者。

这不是完整社区，也不是评论区升级版。它是一个短视频流里的轻量“时间相遇”机制。

## 4. MVP 范围

第一版只做能打动评委和用户的最小闭环：

- Web 版短视频信息流
- 预设视频数据，包含主题标签、情绪标签、视频文案或简介
- 用户刷视频时记录停留行为
- 达到阈值后浮现「流觞卡」
- 卡片展示一句匹配的回响
- 用户可执行三个动作：收下、留一句、继续刷
- 留下的话进入回响库，可在后续演示中被另一个用户刷到
- 单独的「上游」页面展示这张卡从哪里来，以及它如何被封存

第一版暂不做：

- 真正的群聊
- 复杂好友关系
- 完整推荐算法
- 多平台真实视频接入
- 大规模内容审核系统
- 真实年度报告生成

这些可以在路演中作为未来扩展，但不要压到 Demo 第一屏。

## 5. 用户体验流程

### 5.1 刷视频

用户进入一个类抖音的 Web 信息流界面。屏幕中央是竖屏视频，右侧是点赞、评论、收藏、分享按钮，底部是视频标题和作者。

视频内容可以预设为几类：

- 奥德赛 / 归乡 / 远行
- 城市夜路 / 怀旧 / 旧友
- 哲学 / 存在主义 / 孤独
- 职场 / 疲惫 / 自我怀疑
- 电影解读 / 错过 / 重逢

### 5.2 触发瞬间

当用户对同一组情绪标签的视频出现连续停留，例如：

- 同类视频连续停留 2-3 个
- 某个视频停留超过 15 秒
- 重播或展开评论
- 点赞/收藏

系统认为用户进入一个“可被流觞接住”的状态。

前端可以在调试模式中展示 AI 判断过程，正式体验中只轻描淡写地出现一句：

> 你在这条河边停了一会儿。

### 5.3 流觞卡浮现

卡片不是弹窗广告，而是从视频下方或侧边缓慢浮现，像一张半透明的纸笺。

示例：

```text
有人在上游留下了一句话

“我也是很久以后才发现，所谓回家，不一定是回到一个地方。”

来自 127 天前的一次停留

[收下] [留一句] [继续刷]
```

### 5.4 留一句

用户点击「留一句」后，只允许输入一段很短的话，例如 60 字以内：

> 给后来刷到这里的人留一句。

这句话会经过 AI 审核与标签化，进入回响库。后续另一个相似状态的用户可能会刷到它。

### 5.5 封存

当一个主题积累到一定数量的回响，例如 99 条或 24 小时结束，系统将其封存成一个轻量档案：

> 2026 春 · 关于归乡的流觞

封存页包含：

- AI 写的一段短序
- 最有代表性的 5 条回响
- 用户自己的参与痕迹
- 该主题下出现过的关键词流向

## 6. 页面结构

### 首页：视频流

主要承担“刷”和“停”的体验。

必要元素：

- 竖屏视频区域
- 右侧操作栏
- 底部视频描述
- 顶部轻导航：关注 / 推荐 / 流觞
- 触发后的流觞卡
- 可选调试面板：显示当前视频标签、用户停留秒数、触发置信度

### 流觞卡

这是项目的核心 UI，不应被其他功能抢戏。

必要元素：

- 标题：有人在上游留下了一句话
- 主体：一句回响
- 来源：来自多久以前、属于哪个主题
- AI 轻提示：为什么此刻出现，但不能太直白
- 动作：收下 / 留一句 / 继续刷

### 上游页

展示这句话的来处，以及这一轮流觞的更多回响。

必要元素：

- 当前主题名
- AI 短序
- 回响列表
- 代表性标签
- 封存状态

### 我的页面

展示用户收下过的流觞。

必要元素：

- 我的回响
- 我收下的话
- 我参与过的主题
- 可选：年度记忆入口

## 8. 技术架构建议

### 前端

建议使用：

- React / Vite
- Tailwind CSS 或普通 CSS Modules
- Framer Motion 用于卡片浮现动画
- Zustand 或简单 Context 存储当前用户行为

前端重点不是复杂功能，而是质感：

- 类短视频沉浸界面
- 卡片动画克制
- 字体层级干净
- 回响句阅读体验好
- 调试模式能展示 AI 过程，便于路演说明

### 后端

建议使用：

- Node.js + Express / NestJS
- SQLite 或 JSON 文件作为 Demo 数据存储
- REST API

第一版接口：

- `GET /api/videos`
- `POST /api/watch-events`
- `POST /api/moment/analyze`
- `POST /api/cards/match`
- `POST /api/echoes`
- `GET /api/archives/:topic`

### AI 接入

Demo 阶段可以先做“可替换的模拟 AI”：

- 视频标签预设
- 回响库预设
- 规则判断触发
- 规则匹配回响
- 前端展示为 AI 判断结果

如果接入真实大模型，则替换以下模块：

- 视频内容理解
- 用户瞬间判断
- 回响语义匹配
- 流觞卡文案生成
- 用户投稿审核与标签化

## 9. Demo 演示脚本

1. 打开 Web 版短视频信息流。
2. 连续刷到几个“归乡 / 奥德赛 / 远行”主题视频。
3. 用户在第三个视频停留较久。
4. 屏幕上浮现流觞卡：
   > 有人在上游留下了一句话。
5. 展示陌生人的回响句。
6. 点击「留一句」，输入一句给后来者的话。
7. 切换到另一个用户或刷新演示，展示这句话被后来的用户刷到。
8. 打开「上游」页，看到这轮流觞如何被封存。

## 10. 评委能听懂的价值

产品价值：

- 它把短视频中转瞬即逝的情绪停留，变成可被接住、可被传递的卡片体验。

AI 价值：

- AI 不是炫技生成一段话，而是在“视频内容、用户行为、陌生人回响”之间完成一次情感匹配。

交互价值：

- 卡片自然出现在信息流里，不打断用户，但足以让用户停一下。

传播价值：

- 用户会想截图那句话，也会想留下自己的那句话给后来者。
